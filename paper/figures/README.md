# Figure provenance

Every raster figure is regenerated by the project's own toolchain. Two commands
reproduce all of them from scratch:

```bash
dart run tools/paper_figs.dart                 # sim -> paper/figures/data/*.bin + scene.stl
OPENBLAS_NUM_THREADS=1 python3 paper/figures/gen_figures.py   # data -> *.png
```

(The `OPENBLAS_NUM_THREADS=1` guard avoids an intermittent threaded-BLAS
double-free in matplotlib's 3D surface path on this machine.)

| Figure file | What it shows | Source | Status |
|---|---|---|---|
| `pipeline` (TikZ) | input → stroke ops → sim (twin) → outputs | authored inline in `main.tex` | in-tex |
| `impasto_relief.png` | teaser: a painting as simulated impasto relief (pigment + height) | `paper_figs.dart` scene → `gen_figures.py` | **generated** |
| `spinart.png` | 3 blobs flung outward + Coriolis curl by the spin force (420 substeps) | `paper_figs.dart` spin scene | **generated** |
| `dualgeometry.png` | same field as (a) relief render and (b) 3D fabrication surface (STL form) | `paper_figs.dart` scene | **generated** |
| `determinism.png` | same performance replayed twice, fixed timestep → bit-identical (max\|Δ\|=0) | `paper_figs.dart` det scenes | **generated** |

Honesty notes (captions must match these):
- These are **offline matplotlib renders** of the simulator's height + albedo
  fields (relief = hillshade of the height field; colour = the sim's pigment
  albedo, sRGB-encoded). They are **not** the app's GPU shader render, which is
  richer — the captions say so.
- The figure scenes use a slightly softened canvas tooth (amplitude 0.03–0.04)
  and buttery paint (body 1.7) for legibility; representative but not defaults.
- `data/*.bin` are raw `int32 w,h` header + `float32` payload; `scene.stl` is the
  actual watertight export. Regenerated, not committed as canonical.
- The physical-fabrication figures (an actual machine-painted canvas) belong to
  the arXiv **v2** upgrade — they do not exist yet and must not be faked.
